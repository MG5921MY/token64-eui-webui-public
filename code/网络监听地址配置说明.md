# 网络监听地址配置说明

本文档说明如何配置 IPv6 Token WebUI 的监听地址，以平衡安全性和可用性。

---

## 🔒 默认配置

### 直接运行（二进制）

**默认监听**: `127.0.0.1:5000`（仅本地访问）

```bash
# 默认启动
sudo ./ipv6-token-webui

# 访问地址
http://localhost:5000
```

**安全性**: ✅ 高 - 仅本机可访问  
**可用性**: ⚠️ 低 - 无法远程访问

---

### Docker 容器

**默认监听**: `0.0.0.0:5000`（所有网络接口）

```bash
# Docker 启动
docker compose up -d

# 访问地址
http://localhost:5000        # 本地访问
http://<服务器IP>:5000       # 远程访问
```

**安全性**: ⚠️ 中 - 需要配合防火墙  
**可用性**: ✅ 高 - 可远程访问

---

## ⚙️ 自定义配置

### 方法一：命令行参数

```bash
# 仅本地访问
sudo ./ipv6-token-webui -H 127.0.0.1 -p 5000

# 所有接口（需要防火墙保护）
sudo ./ipv6-token-webui -H 0.0.0.0 -p 5000

# 指定网卡 IP
sudo ./ipv6-token-webui -H 192.168.1.100 -p 5000
```

### 方法二：环境变量

```bash
# 设置环境变量
export SERVER_HOST="0.0.0.0"
export SERVER_PORT="5000"

# 启动服务
sudo ./ipv6-token-webui
```

### 方法三：Docker Compose

**编辑 `docker-compose.local.yml`**:

```yaml
services:
  ipv6-token-webui:
    build: .
    container_name: ipv6-token-webui
    network_mode: host
    cap_add:
      - NET_ADMIN
    restart: unless-stopped
    # 自定义监听地址
    command: ["-H", "127.0.0.1", "-p", "5000"]  # 仅本地
    # 或
    # command: ["-H", "0.0.0.0", "-p", "5000"]  # 所有接口
    # 或
    # command: ["-H", "192.168.1.100", "-p", "5000"]  # 指定 IP
```

### 方法四：修改 Dockerfile

**编辑 `Dockerfile`**:

```dockerfile
# 启动命令
# 选项 1: 仅本地访问（最安全）
CMD ["ipv6-token-webui", "-H", "127.0.0.1"]

# 选项 2: 所有接口（需要防火墙）
CMD ["ipv6-token-webui", "-H", "0.0.0.0"]

# 选项 3: 指定 IP
CMD ["ipv6-token-webui", "-H", "192.168.1.100"]
```

## 🛡️ 安全建议

### 场景 1: 本地开发测试

**推荐配置**: `127.0.0.1:5000`

```bash
# 直接运行
sudo ./ipv6-token-webui

# Docker
# 修改 docker-compose.local.yml:
command: ["-H", "127.0.0.1"]
```

**优点**:
- ✅ 最安全，仅本机访问
- ✅ 无需防火墙配置
- ✅ 适合开发测试

**缺点**:
- ❌ 无法远程访问

---

### 场景 2: 内网服务器

**推荐配置**: `0.0.0.0:5000` + 防火墙

```bash
# 1. 启动服务（监听所有接口）
sudo ./ipv6-token-webui -H 0.0.0.0

# 2. 配置防火墙（仅允许内网访问）
sudo ufw allow from 192.168.1.0/24 to any port 5000
sudo ufw enable
```

**优点**:
- ✅ 内网可访问
- ✅ 防火墙保护
- ✅ 适合 NAS、家庭服务器

**缺点**:
- ⚠️ 需要配置防火墙

---

### 场景 3: 公网服务器（不推荐直接暴露）

**推荐配置**: `127.0.0.1:5000` + Nginx 反向代理 + HTTPS

```bash
# 1. 启动服务（仅本地）
sudo ./ipv6-token-webui -H 127.0.0.1

# 2. 配置 Nginx 反向代理
# /etc/nginx/sites-available/ipv6-token-webui
server {
    listen 443 ssl http2;
    server_name your-domain.com;
    
    # SSL 证书
    ssl_certificate /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;
    
    # 安全头
    add_header Strict-Transport-Security "max-age=31536000" always;
    add_header X-Frame-Options "DENY" always;
    add_header X-Content-Type-Options "nosniff" always;
    
    # 反向代理
    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

# 3. 启用配置
sudo ln -s /etc/nginx/sites-available/ipv6-token-webui /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
```

**优点**:
- ✅ 最安全（HTTPS + 反向代理）
- ✅ 可添加身份验证
- ✅ 适合生产环境

**缺点**:
- ⚠️ 配置复杂
- ⚠️ 需要域名和证书

## 🔍 验证配置

### 检查监听地址

```bash
# Linux
sudo netstat -tlnp | grep 5000

# 或
sudo ss -tlnp | grep 5000

# 预期输出示例：
# 127.0.0.1:5000  - 仅本地
# 0.0.0.0:5000    - 所有接口
# 192.168.1.100:5000 - 指定 IP
```

### 测试访问

```bash
# 本地测试
curl http://localhost:5000/api/system/info

# 远程测试（从另一台机器）
curl http://<服务器IP>:5000/api/system/info

# 如果无法访问，检查：
# 1. 监听地址是否正确
# 2. 防火墙是否允许
# 3. 网络是否连通
```

## ⚠️ 安全警告

### ❌ 不要这样做

```bash
# ❌ 在公网服务器上直接监听 0.0.0.0 且无防火墙
sudo ./ipv6-token-webui -H 0.0.0.0

# 风险：
# - 任何人都可以访问
# - 可能被攻击
# - 配置可能被篡改
```

### ✅ 应该这样做

```bash
# ✅ 方案 1: 仅本地 + SSH 隧道
sudo ./ipv6-token-webui -H 127.0.0.1
# 远程访问使用 SSH 隧道:
# ssh -L 5000:localhost:5000 user@server

# ✅ 方案 2: 监听所有接口 + 防火墙
sudo ./ipv6-token-webui -H 0.0.0.0
sudo ufw allow from 192.168.1.0/24 to any port 5000

# ✅ 方案 3: 仅本地 + Nginx 反向代理 + HTTPS
sudo ./ipv6-token-webui -H 127.0.0.1
# 配置 Nginx（见上文）
```

## 🐳 Docker 特别说明

### 为什么 Docker 默认使用 0.0.0.0？

**原因**:
1. Docker 容器有独立的网络命名空间
2. 容器内的 `127.0.0.1` 只能容器内部访问
3. 需要监听 `0.0.0.0` 才能从宿主机访问

**安全措施**:
```yaml
# docker-compose.local.yml
services:
  ipv6-token-webui:
    # 方案 1: 使用 host 网络（容器直接使用宿主机网络）
    network_mode: host
    command: ["-H", "127.0.0.1"]  # 可以使用 127.0.0.1
    
    # 方案 2: 使用桥接网络 + 端口映射
    # network_mode: bridge  # 默认
    ports:
      - "127.0.0.1:5000:5000"  # 仅本地访问
      # 或
      # - "5000:5000"  # 所有接口（需要防火墙）
    command: ["-H", "0.0.0.0"]  # 容器内监听所有接口
```

### Docker 安全配置示例

**仅本地访问**:
```yaml
services:
  ipv6-token-webui:
    build: .
    ports:
      - "127.0.0.1:5000:5000"  # 仅绑定到本地
    command: ["-H", "0.0.0.0"]
```

**内网访问**:
```yaml
services:
  ipv6-token-webui:
    build: .
    ports:
      - "5000:5000"  # 所有接口
    command: ["-H", "0.0.0.0"]
    # 配合宿主机防火墙使用
```

## 📞 常见问题

### Q1: 为什么无法从其他机器访问？

**检查清单**:
1. 监听地址是否为 `0.0.0.0` 或指定 IP？
2. 防火墙是否允许端口 5000？
3. 网络是否连通？

```bash
# 检查监听地址
sudo netstat -tlnp | grep 5000

# 检查防火墙
sudo ufw status

# 测试网络连通性
ping <服务器IP>
```

### Q2: Docker 容器内无法访问？

**原因**: 容器内监听 `127.0.0.1`

**解决**:
```bash
# 修改为监听 0.0.0.0
docker run -d -p 5000:5000 ipv6-token-webui -H 0.0.0.0
```

### Q3: 如何同时支持本地和远程访问？

**方案 1: 监听 0.0.0.0 + 防火墙**
```bash
sudo ./ipv6-token-webui -H 0.0.0.0
sudo ufw allow from 192.168.1.0/24 to any port 5000
```

**方案 2: 监听 127.0.0.1 + SSH 隧道**
```bash
# 服务器
sudo ./ipv6-token-webui -H 127.0.0.1

# 客户端
ssh -L 5000:localhost:5000 user@server
# 然后访问 http://localhost:5000
```

**推荐配置**:

| 环境 | 监听地址 | 命令 |
|------|---------|------|
